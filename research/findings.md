# Antoine/NATS vulnerability research findings

Date: 2026-10-19  
Scope: run-owned NATS broker on `127.0.0.1`, Antoine Gazebo SITL, local demo authority, X500 in Gazebo.

## Finding AVD-001 — Unauthenticated setpoint injection can deny takeoff

**Result:** Confirmed in the local demo profile. The modified setpoint was accepted by Antoine's typed parser. The controller rejected its changed target against the locally signed execution grant and emitted an explicit neutral stop 38 ms after publication began. Independent Gazebo pose showed no waypoint reached and 0.01 m horizontal travel (measurement resolution), with a 0.23 m transient climb.

**Precondition:** A process can connect to the local NATS listener and publish to `furia.gzsitl.setpoint.drone-1`. The test did not escape loopback or use a private key.

**Mechanism:** The 2.1.0 setpoint payload has neither a signature field nor a `runId` field. Its mission, vehicle, task, and admission fields are copyable from a live message; the run identity comes from the run-owned broker, signed grant, and independent flight evidence. A higher sequence is accepted into the controller's replaceable-setpoint state before the flight loop checks the exact target against the grant. The test changed east position from 0 m to 2 m and used sequence 1,000,000. The exact-target grant check stopped actuation, while the consumed high-water sequence caused subsequent legitimate lower-sequence setpoints to be rejected.

**Impact and limits:** Availability loss at takeoff for a client with same-host broker access. The unauthorized target was not flown. This is an unqualified local integration using a local test authority, not evidence of a production/Core or remotely reachable vulnerability.

**Evidence:** `antoine-waypoint-injection-20261019T092237Z-34896/research-result.json`. Matching Featherstone baseline `antoine-gz-flight-20261019T092017Z` passed both waypoints (9.997 m climb, 13.893 m horizontal travel).

A fresh control and paired mutation run also completed in this checkout: baseline `antoine-baseline-20261019T102949Z-92149` passed all five eligibility gates (10.08 m peak altitude, 13.882 m horizontal travel). Injection `antoine-waypoint-injection-20261019T103111Z-4038` produced an explicit neutral stop 35 ms after publication, with zero horizontal travel and 0.464 m peak altitude. The engine and local authority scope matched, so the report marks the runs comparable; the deltas are descriptive measurements from separate runs.

Five fresh injection runs (`antoine-waypoint-injection-20261019T143538Z-89448`, `antoine-waypoint-injection-20261019T144607Z-19239`, `antoine-waypoint-injection-20261019T144739Z-30621`, `antoine-waypoint-injection-20261019T145040Z-41593`, `antoine-waypoint-injection-20261019T145208Z-47080`) have valid manifests, matching run identity, stable provenance, independent pose/actuator gates, and qualify as local attack observations. Each published one +2 m east mutation, the typed parser accepted it, the controller emitted a same-run neutral stop 26–50 ms after publication, and horizontal travel remained 0 m. One run logged a transient child `setpgid` permission error, but its independent proof gates still passed. Two additional attempts remain unqualified: `143402Z-84650` predates the corrected impact classifier; `144908Z-35212` changed the forwarder build receipt during the run. The fresh five-run repeatability criterion is met for the local denial observation. These are not quantitative baseline comparisons because no injection run completes all flight legs.

Reproduction `antoine-waypoint-injection-20261019T161430Z-5765` also passed the causal mutation/stop gates: one unsigned +2 m east setpoint with sequence 1,000,000 was parsed, and same-run neutral actuator output followed 41 ms after publication. Independent pose showed 0.40 m climb, 0.00 m horizontal travel, and neither waypoint reached. This reproduces denial of takeoff, while the overall report deliberately remains `demo_unqualified` because this local test-authority run is not production authority evidence. Its evidence manifest digest check passed; the manifest is unsigned.

Five fresh authorized descent controls were run with the Antoine proof's four-leg profile ending at 0.15 m. Four runs (`antoine-baseline-20261019T151544Z-20031`, `151840Z-43550`, `152117Z-63131`, `152631Z-89754`) passed identity, provenance, all-leg, independent pose, actuator-neutralization, and measured ground-dwell gates and classify `qualified_baseline`. Their horizontal travel ranged 13.885–13.893 m, peak altitude 9.709–9.772 m, and observed ground dwell 8.636–57.158 s. One run (`antoine-baseline-20261019T152354Z-79659`) is retained as inconclusive: the controller stopped early, the final leg was missed, and no ground dwell was measured. All five manifest digests verify. This qualifies a local authorized flight comparison baseline only; `physicalSafeStopPassed` remains null/false because Gazebo pose plus actuator neutralization is not a physical safe-stop or controlled-landing claim.

## Setpoint sequence poisoning and recovery observation

The bounded runner `research/run-antoine-scenario.sh sequence-poisoning` publishes one changed-target setpoint with sequence `1,000,000`, then restores the authorized target with sequence `1,000,001`. Fresh run `antoine-sequence-poisoning-20261019T151026Z-7321` passed the run identity, two-publication, event-order, provenance, independent-pose, stop, recovery-acceptance, and actuator-progress gates. Antoine resumed actuator sequence progress 67 ms after recovery publication. Manifest integrity passed. Gazebo pose recorded zero horizontal travel and no completed waypoint, so this is an ingress/actuator recovery observation, not a completed flight recovery or physical safety claim. The controller process was not restarted; restart persistence is inferred from the setpoint subscriber's in-memory sequence variable and remains unmeasured. Earlier qualifying run `antoine-sequence-poisoning-20261019T150829Z-1689` measured 64 ms.

**Mitigation to evaluate:** Authenticate/authorize publishers per NATS subject; sign the setpoint body against the run, vehicle, grant sequence, task and target; and do not advance an anti-replay/high-water cursor until authorization and grant binding pass. A duplicate NATS identity check alone is not sufficient if arbitrary local processes share the same account.

## Finding AVD-002 — Same-host clients can read mission and state subjects

**Result:** Confirmed for four selected subjects without NATS credentials. Twelve messages exposed the mission target `[0,0,10]`, run/task identifiers, grant metadata, vehicle pose, and Vigie admission metadata. Signature values were redacted from the stored capture.

**Precondition and limits:** A local process can reach the loopback broker. The profile binds NATS to `127.0.0.1`; this is a same-host disclosure/hardening issue, not a remote exposure finding. Read access did not grant actuator authority.

**Evidence:** `antoine-nats-observation-20261019T092915Z-56633/research-nats-observation.json`. That earlier capture's flight proof failed, so it made no motion claim. Current reproduction `antoine-nats-observation-20261019T121548Z-23185` read one message from each of the same four subjects without credentials; its separate flight proof also passed both waypoints (10.01 m climb, 13.89 m travel). The read remains a same-host disclosure/hardening result and makes no actuator-authority claim.

Latest reproduction `antoine-nats-observation-20261019T161148Z-97391` captured one message on each selected subject without credentials while the independent flight proof passed both legs (10.01 m climb, 13.88 m horizontal travel) and actuator neutralization. Both run manifest digest checks passed; they are unsigned and remain a same-host observation only.

It also reports controller-state coalescing diagnostics per vehicle; these are descriptive and do not qualify flight outcomes. A measured tilt breach is reported as a failed baseline with a named reason; missing orientation remains inconclusive. The report evaluates scripted formation at a shared in-flight timestamp when each vehicle reached its final waypoint. Flight reports publish their absolute Gazebo clock origin; the swarm report adds that origin before cross-vehicle pose comparison. It preserves post-neutralization pose separately. Antoine telemetry binds `executionGrantActive` and controller/state cadence to the run and callsign; grant revocation remains separate from arming. Authority evidence records bounded per-run grant, setpoint, and waypoint-reached events, correlated by run, callsign, sequence, target, and timestamp; the summary compares them to the independent evaluator and reports the first unreached waypoint and last authority progress. Cadence qualification requires at least 20 valid telemetry samples, a warmed 64-sample state estimator, and no more than 1.1 controller ticks per fresh state sample (10% tolerance). The report separates `behaviorStatus`, `probeStatus`, and `baselineStatus`; aggregate status and exit code cannot pass while any required baseline gate is unavailable. The summarizer returns 0 for passed, 1 for measured failure, and 2 for inconclusive evidence.

### Scripted swarm behaviours

`research/swarm_behavior.py` now generates a deterministic plan for `lanes`, `column`, `vee`, `rendezvous`, or `split` and writes it to `research-swarm-plan.json` before launch. Non-lane plans use a three-point path per vehicle: climb to a fixed per-vehicle transit altitude layer, cross lanes at that layer, then descend at the separated final slot. The plan records both a static path-clearance estimate and a synchronized estimate that assumes all vehicles start together at the same effective speed; the planner rejects a plan below a 1 m lab floor. The runner derives its flight-time budget from the longest planned path. Every vehicle still runs its own local authority over a fixed waypoint list: the runner cannot push live setpoints into another vehicle's controller, and the local grant is bound to the planned target. After the flight, `summarize_antoine_two_drone_flight.py` compares the final Gazebo poses with the planned final slots and adds gates for final-slot tolerance, formation-shape distance, pairwise separation, and (for rendezvous/split) convergence or subgroup separation. A run is qualified only when those pose gates and the original per-vehicle flight gates pass. At the default 8 m spacing, final slots are at least 5 m apart, matching S1's default minimum separation, but this profile does not start S1 or enforce its ORCA3D avoidance. These are scripted geometry checks, not closed-loop formation control, consensus, or dynamic collision avoidance.

### MAVLink telemetry fan-out (optional)

With `ANTOINE_SWARM_MAVLINK=1`, the runner builds the tracked `research/antoine-mavlink-jetstream-bridge`, starts one process per callsign with a distinct system ID and loopback UDP port pair, and runs `research/mavlink_swarm_probe.py` for a bounded receive window. The probe validates MAVLink v1/v2 framing and checksums, records per-callsign HEARTBEAT, GPS_RAW_INT, and GLOBAL_POSITION_INT counts, and checks that each socket sees only its own system ID. This evidences the telemetry path from `furia.telemetry.<callsign>` to MAVLink. This swarm option uses the bridge's `antoine-nats` mode and does not evidence GCS control: its arm/disarm requests target Antoine's native control subject, while the Gazebo profile uses the separate `gazebo-nats` mode to route GCS requests through the run-owned local authority. The swarm probe sends no MAVLink command. The bridge source and lockfile are tracked with the lab; bridge compilation and live MAVLink/Gazebo acceptance still require their own successful checks.

## Evidence handling and comparison

The native Antoine launcher starts the checkout-owned research console at `http://127.0.0.1:8001/attacks/research`; `./research/console.sh` also supports standalone start/status/stop. The legacy full and lite Docker management UI can show the same read-only findings and evidence mount. The console indexes result JSON from each local run and offers downloads only for an explicit allowlist of research reports. It does not serve run directories: `run-keys.txt`, actuator sequence state, and launcher logs remain unavailable through the web route.

Each completed runner writes `research-evidence-manifest.json`, with normalized measurements and SHA-256 digests for public evidence artifacts, including the raw neutral applier actuator audit and source provenance. Provenance records dependency revisions, dirty-state digests, and hashes for relevant source files and binaries without exposing host paths. The wrapper builds Antoine before preflight capture and records all three runtime executables, the selected Gazebo plugin, the signed forwarder, and its exact build receipt before and after the run. This identifies local inputs but does not attest which binaries the operating system loaded. The manifest excludes itself and secret or runtime-control files. Injection causality requires a same-run neutral actuator stop after publication plus independent pose and actuator evidence. Baseline deltas require engine, authority, flight, pose, and actuator gates on both runs. CSV export checks evidence digests and reports signature authentication separately. Local Ed25519 signatures are optional; configure `DVD_RESEARCH_SIGNING_KEY` to sign manifests and pin the generated public key with `DVD_RESEARCH_TRUSTED_PUBLIC_KEY` for trusted signature verification. Unsigned runs remain explicitly unsigned. To export comparable rows from manifests:

```bash
uv run --project research python research/export_research_csv.py
uv run --project research python research/verify_evidence_manifest.py build_logs/research/antoine-scenarios/RUN_ID
```

The exporter writes `build_logs/research/antoine-research-summary.csv`; pass `--output PATH` or `--root DIR` to select another output or evidence directory. It preserves incomplete evidence as `inconclusive`, distinguishes observation-only runs, and only labels a scenario result qualified when its core gates are present. Camera columns preserve topic discovery, publisher presence, frame count, dimensions, and an observation status such as `topic_not_listed_in_probe_partition`. GPS-only rows say `separate_camera_rehearsal` because camera rendering is isolated from flight experiments. Existing runs can be indexed without rerunning the simulator.

The manifest verifier checks exact run-directory identity, safe relative paths, file presence, sizes, and SHA-256 digests. Its `signatureStatus` is separate: `unsigned`, a valid but unpinned signature, a trusted pinned signature, a bad signature, and a manifest-digest mismatch are distinct states. A trusted signature proves possession of the configured local key, not which executable the operating system loaded. Treat `evidenceIntegrity`, `manifestAuthentication`, and `runStatus` as separate properties.
